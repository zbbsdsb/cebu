# Security Policy

## Supported Versions

We actively support the following versions of Cebu with security updates:

| Version | Supported          |
| ------- | ------------------ |
| 0.8.x   | :white_check_mark: |
| < 0.8   | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability in Cebu, please report it to us responsibly. We appreciate your efforts to disclose the issue privately and give us an opportunity to address it before making it public.

### How to Report

Please report security vulnerabilities by:

1. **Email**: Send a detailed report to security@oasis-company.com
2. **GitHub Security Advisories**: Use the [GitHub Security Advisories](https://github.com/ceaserzhao/cebu/security/advisories) feature to create a private report

### What to Include

When reporting a vulnerability, please include:

- A clear description of the vulnerability
- Steps to reproduce the issue
- Potential impact of the vulnerability
- Any suggested fixes or workarounds (if available)
- Your contact information for follow-up

### Response Process

We will respond to your report within:

- **Acknowledgment**: Within 48 hours of receiving your report
- **Initial Assessment**: Within 1 week
- **Fix Development**: Depending on complexity, typically within 2-4 weeks
- **Public Disclosure**: Coordinated with you after the fix is released

### What to Expect

- We will keep you informed about the progress of your report
- We may ask for additional information or clarification
- We will credit you in the security advisory (unless you prefer to remain anonymous)
- We will not disclose your identity without your permission

## Security Advisories

Once a vulnerability is fixed, we will publish a security advisory in:

- The [GitHub Security Advisories](https://github.com/ceaserzhao/cebu/security/advisories) page
- The project's [CHANGELOG.md](CHANGELOG.md)
- Our release notes

## Best Practices for Users

To ensure the security of your projects using Cebu:

1. **Keep dependencies updated**: Use the latest supported version of Cebu
2. **Review changes**: Read release notes and security advisories before updating
3. **Report issues**: If you discover a vulnerability, please report it to us
4. **Contribute**: Help improve security by reviewing code and reporting potential issues

## Security in Development

We are committed to developing Cebu securely:

- We follow secure coding practices
- We perform regular code reviews
- We use automated security scanning tools
- We maintain an up-to-date dependency chain
- We welcome security audits and feedback
